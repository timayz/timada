# Evento — Event Sourcing & CQRS for Rust (2.0.0-alpha.26)

Evento is an event-sourcing toolkit built around an `Executor` abstraction (SQLite / MySQL / PostgreSQL via sqlx, or Fjall embedded). Events are serialized with [`bitcode`](https://crates.io/crates/bitcode); aggregate/handler boilerplate is generated by `evento-macro`.

Source: <https://github.com/timayz/evento/tree/v2.0.0-alpha.26>

Companion references in this directory:

- [`macros.md`](./macros.md) — `#[evento::aggregate]`, `#[evento::projection]`, `#[evento::handler]`, `#[evento::subscription]`, `#[evento::subscription_all]`, `#[derive(Cursor)]`: what they expand to.
- [`subscriptions.md`](./subscriptions.md) — `SubscriptionBuilder`, routing keys, retries, shutdown, `Context`, `Data` injection.
- [`executors.md`](./executors.md) — SQL pool setup, migrations, Fjall, `Evento` / `EventoGroup` / `Rw`, raw reads with `Reader`.

## Cargo setup

```toml
[dependencies]
# `version = "2"` will NOT resolve a pre-release — pin the alpha exactly:
evento  = { version = "=2.0.0-alpha.26", features = ["sqlite"] }   # or "postgres", "mysql", "fjall"
bitcode = "0.6"
sqlx    = { version = "0.9", features = ["runtime-tokio", "sqlite"] }
tokio   = { version = "1", features = ["full"] }
anyhow  = "1"
```

Feature flags on the `evento` crate:

| Feature   | Effect |
|-----------|--------|
| `macro`   | Procedural macros (on by default) |
| `sql`     | Enables `sqlite` + `mysql` + `postgres` |
| `sqlite`  | `sqlx::Sqlite` executor + migrator |
| `mysql`   | `sqlx::MySql` executor + migrator |
| `postgres`| `sqlx::Postgres` executor + migrator |
| `fjall`   | Embedded `Fjall` executor (no migrator); implies `rw` |
| `group`   | `EventoGroup` multi-executor reads |
| `rw`      | `Rw<R, W>` read/write-split executor |

(The `evento-sql`/`evento-fjall` crates additionally have an `accord` feature for the experimental `evento-accord` replicated event store — CEP-15 consensus; not exposed through the main crate's features.)

## Migrating from ≤ alpha.20 (the alpha.21 API redesign)

Architecture and on-disk layout are unchanged (no data migration). Renames only:

| Old | New |
|-----|-----|
| `#[evento::aggregator]` | `#[evento::aggregate]` |
| `Aggregator` / `aggregator_type()` | `Aggregate` / `aggregate_type()` |
| `AggregatorEvent`, `AggregatorExecutor` | `AggregateEvent`, `AggregateExt` |
| `Event.aggregator_id` / `.aggregator_type` | `Event.aggregate_id` / `.aggregate_type` |
| `ReadAggregator::{new,aggregator,id,event}` | `EventFilter::{exact,by_type,by_id,by_event}` |
| `AggregatorBuilder` | `WriteBuilder` |
| `evento::aggregator(id)` | `evento::append(id)` |
| `ProjectionAggregator` / `.aggregator()` | `ProjectionAggregate` / `.write()` |
| `Projection::new::<A>(id)` | `Projection::new::<A>()` + `.load(id)` |
| `.safety_check()` | `.strict()` |
| `.accept_failure()` | `.continue_on_error()` |
| `.unretry_start()` / `.unretry_execute()` | `.no_retry()` + `.start()` / `.run_once()` |
| `.execute(&exec)` (subscription) | `.run_once(&exec)` |

`ProjectionAggregate::aggregate_id()` is now **required** (previously a panicking default). `#[evento::subscription_all]` actually works now (pre-alpha.21 it matched zero events).

## Mental model

```
                  ┌────────────────┐
write API ──────► │   Executor     │ ◄────── read API (Projection / SubscriptionBuilder)
(create/append)   │ (SQL / Fjall)  │
                  └────────────────┘
                           ▲
                           │  events keyed by aggregate_type + aggregate_id + version
                           │  optimistic concurrency on `original_version`
```

- **Aggregate** — a type identifier (`"my_crate/BankAccount"`). Each aggregate *instance* has an ID (typically a ULID).
- **Event** — an immutable fact persisted under one aggregate at an incrementing `version`. Serialized as bitcode.
- **Projection** — a read model rebuilt by replaying events through `#[evento::handler]` functions.
- **Subscription** — a long-running task that streams new events through handlers and acknowledges its cursor.
- **Executor** — the storage backend. All write/read APIs are generic over `Executor`.

## Defining events — `#[evento::aggregate]`

Each variant becomes its own public struct. The enum becomes a unit struct used as the aggregate handle.

```rust
#[evento::aggregate]
pub enum BankAccount {
    /// doc comments are preserved on the generated struct
    AccountOpened { owner_id: String, initial_balance: i64 },
    MoneyDeposited { amount: i64, transaction_id: String },
    MoneyWithdrawn { amount: i64 },
    AccountClosed,                       // unit variant → unit struct
}
```

Expansion (sketch):

- `pub struct AccountOpened { pub owner_id: String, pub initial_balance: i64 }` (+ for each variant)
- Derives auto-added: `Debug, Clone, PartialEq, Default, bitcode::Encode, bitcode::Decode`
- `impl evento::Aggregate for AccountOpened` returning `aggregate_type() = "{cargo_pkg_name}/BankAccount"`
- `impl evento::AggregateEvent for AccountOpened` returning `event_name() = "AccountOpened"`
- `pub struct BankAccount;` with `impl evento::Aggregate` (used in `Projection::new::<BankAccount>()`)

**Aggregate type is `"{CARGO_PKG_NAME}/{EnumName}"`** — derived at compile time. Renaming the crate changes the persisted type string, so plan for that.

Pass extra derives with `#[evento::aggregate(serde::Serialize, serde::Deserialize)]`.

## Writing events — `create()` / `append()`

`evento::create()` builds events for a brand-new aggregate (ULID auto-generated; `commit` returns the id). `evento::append(id)` targets an existing aggregate and **requires `original_version`** for optimistic concurrency.

```rust
// New aggregate
let account_id = evento::create()
    .event(&AccountOpened { owner_id: "u1".into(), initial_balance: 1000 })
    .requested_by("user-1")           // standard metadata
    .routing_key("accounts")          // optional; locked once set
    .commit(&executor)
    .await?;

// Append to an existing aggregate
evento::append(&account_id)
    .original_version(1)              // current version BEFORE this commit
    .event(&MoneyDeposited { amount: 100, transaction_id: tx.into() })
    .event(&MoneyDeposited { amount: 50,  transaction_id: tx2.into() }) // multi-event batch is atomic
    .commit(&executor)
    .await?;
```

`WriteBuilder` methods:

| Method | Purpose |
|--------|---------|
| `.event(&E)` | Append an event (must impl `AggregateEvent + bitcode::Encode`); multiple calls = atomic batch |
| `.original_version(u16)` | Expected current version; mismatch → `WriteError::InvalidOriginalVersion` |
| `.routing_key(impl Into<String>)` / `.routing_key_opt(Option<String>)` | Partition key; locked after first set |
| `.metadata(key, &value)` | Insert one bitcode-encoded metadata key |
| `.metadata_from(impl Into<Metadata>)` | Replace the whole metadata blob |
| `.requested_by(user_id)` / `.requested_as(user_id)` | Standard metadata setters |
| `.commit(&executor)` | Persist; returns the aggregate ID |

`WriteBuilder::new(id)` / `WriteBuilder::ids(vec![...])` construct builders directly; `ids` derives the aggregate id by SHA3-hashing a list of input IDs (`evento::hash_ids`) — useful for relationship aggregates.

`WriteError` variants: `InvalidOriginalVersion`, `MissingData` (no `.event()` called), `Unknown(anyhow::Error)`, `SystemTime(...)`.

**Routing key is "sticky" on the aggregate.** `commit` reads the *first* event of the aggregate and reuses its `routing_key`; the `.routing_key(...)` call on appends is ignored if events already exist.

## Reading state — `Projection` + `LoadBuilder`

A projection is defined once (handlers, no id), then used to `.load(id)` on demand or kept auto-updated via `.subscription(key)`.

```rust
use evento::{metadata::Event, projection::Projection};

#[evento::projection(bitcode::Encode, bitcode::Decode)]  // extra derives enable free snapshots
#[derive(Debug)]
pub struct AccountView {
    pub balance: i64,
    pub owner: String,
}

#[evento::handler]
async fn on_account_opened(
    event: Event<AccountOpened>,
    view: &mut AccountView,
) -> anyhow::Result<()> {
    view.owner = event.data.owner_id.clone();
    view.balance = event.data.initial_balance;
    Ok(())
}

#[evento::handler]
async fn on_money_deposited(
    event: Event<MoneyDeposited>,
    view: &mut AccountView,
) -> anyhow::Result<()> {
    view.balance += event.data.amount;
    Ok(())
}

let account: Option<AccountView> = Projection::<_, AccountView>::new::<BankAccount>()
    .handler(on_account_opened())
    .handler(on_money_deposited())
    .strict()                        // fail if an unhandled event is seen
    .load(&account_id)               // → LoadBuilder
    .execute(&executor)
    .await?;
```

Notes:

- `Projection::<_, P>::new::<A>()` — first generic is `Executor` (usually inferred), second is the projection state type; `A` is the aggregate handle (the unit struct from `#[evento::aggregate]`). **No id at construction.**
- `.handler(handler_fn())` — call site is `handler_fn()` (the macro generates a zero-sized constructor of the same name). Duplicate registration for one event type panics.
- `.strict()` — by default unknown events are skipped; with strict on, an unhandled event makes `execute` return `Err`.
- `.skip::<MyEvent>()` — register a no-op handler so `strict()` passes for events you don't need.
- `.data(value)` — insert shared data accessible via the context inside handlers; reused by both `.load(..)` and `.subscription(..)`.
- `.revision(u16)` — bump to invalidate existing snapshots and force a rebuild.
- `.tombstone::<MyEvent>()` — that event marks the aggregate deleted: `.load(..).execute(..)` short-circuits to `Ok(None)`, and the auto-update subscription routes it to `Snapshot::drop_snapshot`.
- `.load(id)` / `.load_ids(vec![a, b])` → `LoadBuilder` (the ids variant hashes via `hash_ids` for multi-id state).
- On `LoadBuilder`: `.aggregate::<Other>(other_id)` / `.aggregate_raw(type, id)` register **secondary aggregates** whose events also feed this projection. A secondary aggregate not registered is assumed **co-keyed** (shares the primary's id).
- `.execute(&executor)` returns `Ok(None)` if no events exist (and no snapshot), `Ok(Some(P))` otherwise. It reads 100 events per call and **errors with `"Too busy"`** if a single load can't finish in one batch — use snapshots for long histories.
- In custom `Snapshot` impls, the projection `Context` exposes `context.aggregate::<Other>().await` to read a registered secondary aggregate's id (panics if not registered), plus `get_snapshot` / `take_snapshot` / `drop_snapshot` and `extract::<T>()` for `.data(..)` values.

### Snapshots

Any `P: bitcode::Encode + bitcode::DecodeOwned + ProjectionCursor + Send + Sync` automatically gets a `Snapshot<E>` impl backed by the executor's snapshot storage — `execute` restores it before replaying. The `#[evento::projection]` macro does **not** add the bitcode derives; pass them as macro args (`#[evento::projection(bitcode::Encode, bitcode::Decode)]`). Override `Snapshot::restore` / `take_snapshot` / `drop_snapshot` for custom storage (e.g. your own SQL read-model table).

### `ProjectionAggregate` — emitting events from projections (command pattern)

```rust
use evento::ProjectionAggregate;

impl ProjectionAggregate for AccountView {
    fn aggregate_id(&self) -> String { self.id.to_owned() }   // REQUIRED — no default
}

// Command: load → validate → write
let Some(view) = projection.load(&id).execute(&executor).await? else {
    anyhow::bail!("not found");
};
view.write()?                        // WriteBuilder pre-filled with id + original_version
    .event(&MoneyWithdrawn { amount: 50 })
    .commit(&executor)
    .await?;
```

`aggregate_version()` reads the version off the projection's cursor — always in sync with what was replayed.

### Auto-updated projections — `.subscription(key)`

```rust
let sub = Projection::<_, AccountView>::new::<BankAccount>()
    .handler(on_account_opened())
    .handler(on_money_deposited())
    .subscription("account-view")     // define-once, auto-update
    .routing_key("accounts")          // or .all(); default = executor default / unkeyed
    .start(&executor)
    .await?;
// sub.shutdown().await?;
```

`ProjectionSubscription` re-loads the affected aggregate id on every incoming event and persists the snapshot. Builder methods: `.routing_key(k)`, `.all()`, `.chunk_size(n)`, `.retry(n)`, `.no_retry()`, `.delay(d)`, `.continue_on_error()`, then `.start(&exec)` or `.run_once(&exec)`. **Co-keying caveat:** in subscription mode every secondary aggregate is assumed to share the primary's id; if it doesn't, its events won't be applied — use `LoadBuilder::aggregate` on demand or a manual `SubscriptionBuilder` instead.

## Continuous processing — `SubscriptionBuilder`

```rust
use std::time::Duration;
use evento::{Executor, metadata::Event, subscription::{Context, SubscriptionBuilder}};

#[evento::subscription]
async fn notify_on_deposit<E: Executor>(
    ctx: &Context<'_, E>,
    event: Event<MoneyDeposited>,
) -> anyhow::Result<()> {
    // side effects: emails, read-model writes, outbound API calls
    Ok(())
}

let subscription = SubscriptionBuilder::<evento::Sqlite>::new("deposit-notifier")
    .handler(notify_on_deposit())
    .routing_key("accounts")          // only events with this key
    .chunk_size(100)                  // default 300
    .retry(5)                         // default 30, exponential backoff
    .delay(Duration::from_secs(10))   // initial pause before first poll
    .start(&executor)
    .await?;

// graceful shutdown
subscription.shutdown().await?;
```

Key behaviours:

- `.start(&executor)` spawns a tokio task. It wakes instantly on in-process writes (`Executor::write_watch`) and re-polls every 250ms as a fallback (`.poll_interval(d)` to change); events are processed in `chunk_size` batches with the cursor `acknowledge`d after each event.
- `.run_once(&executor)` (no spawn) drains pending events once and returns; pair with `.no_retry()` for a single pass.
- `.continue_on_error()` — log + continue instead of stopping on handler errors.
- `.all()` — process *all* events regardless of routing key. Default with no routing key = the executor's `default_routing_key()` if set, else only unkeyed events.
- `.routing_key(k)` — also prefixes the subscription key to `"{routing_key}.{key}"` for per-partition cursor tracking.
- `.strict()` / `.skip::<EventType>()` — fail on, or explicitly ignore, unhandled events.
- `.data(v)` — inject shared data readable via `ctx.extract::<T>()`.
- `.handler(h)` — one handler per (aggregate_type, event_name); duplicates panic.

Use **`#[evento::subscription_all]`** to receive every event of an aggregate type without decoding the payload (the handler takes `RawEvent<Aggregate>` instead of `Event<EventType>`):

```rust
use evento::metadata::RawEvent;

#[evento::subscription_all]
async fn audit<E: Executor>(ctx: &Context<'_, E>, e: RawEvent<BankAccount>) -> anyhow::Result<()> {
    tracing::info!(name = %e.name, version = e.version, id = %e.aggregate_id, "audit");
    Ok(())
}
```

## Executors

| Type                  | Crate        | When |
|-----------------------|--------------|------|
| `evento::Sqlite`      | `evento-sql` (feature `sqlite`) | `Sql<sqlx::Sqlite>` |
| `evento::Postgres`    | `evento-sql` (feature `postgres`) | `Sql<sqlx::Postgres>` |
| `evento::MySql`       | `evento-sql` (feature `mysql`) | `Sql<sqlx::MySql>` |
| `evento::Fjall`       | `evento-fjall` (feature `fjall`) | Embedded LSM, no external DB |
| `evento::Evento`      | `evento-core` | Type-erased `Arc<Box<dyn Executor>>`; carries an optional default routing key |
| `evento::EventoGroup` | feature `group` | Read from multiple executors, write to first |
| `evento::Rw<R, W>`    | feature `rw` | CQRS: separate read/write databases |

Setup pattern (SQL):

```rust
let pool = sqlx::SqlitePool::connect("sqlite:events.db").await?;
let mut conn = pool.acquire().await?;
evento::sql_migrator::new::<sqlx::Sqlite>()?          // the DB type is REQUIRED on `new`
    .run(&mut *conn, &evento::migrator::Plan::apply_all())
    .await?;
drop(conn);

let executor: evento::Sqlite = pool.into();   // `From<Pool<DB>> for Sql<DB>`
```

`Sql<DB>` is `Clone` (the inner pool is `Arc`), so cheap to pass to handlers, web state, etc.

Fjall:

```rust
let executor = evento::Fjall::open("./events")?;              // creates dirs if missing
// or: Fjall::from_database(db) for a custom fjall::Database config
executor.persist()?;                                          // force fsync
```

Multi-tenancy: `evento::Evento::new(executor).default_routing_key("tenant-a")` stamps unkeyed writes with the default and scopes subscriptions built on it — see [`subscriptions.md`](./subscriptions.md).

## Metadata

`Metadata` is a bitcode-serialized `HashMap<String, Vec<u8>>` keyed by string, plus a ULID `id`.

```rust
use evento::metadata::Metadata;

let mut meta = Metadata::default();
meta.set_requested_by("user-123");
meta.set_requested_as("impersonated-789");

evento::create()
    .event(&MyEvent { /* … */ })
    .metadata_from(&meta)             // or: .metadata("KEY", &value) per key
    .commit(&executor).await?;

// On the read side, `Event<MyData>` derefs to `evento::Event`, so:
if let Ok(by) = event.metadata.requested_by() { /* … */ }
let custom: MyType = event.metadata.try_get("KEY")?;
```

`MetadataError::NotFound | Decode(bitcode::Error)`.

## Reading events directly — `EventFilter` + cursor pagination

All reads through the `Executor::read` API use GraphQL-style cursors.

```rust
use evento::{EventFilter, cursor::Args};

let page = executor.read(
    Some(vec![EventFilter::by_id("crate/BankAccount", &account_id)]),
    None,                                  // RoutingKey filter (None = ignore)
    Args::forward(20, None),               // first 20
).await?;

let next = executor.read(
    Some(vec![EventFilter::by_type("crate/BankAccount")]),
    None,
    Args::forward(20, page.page_info.end_cursor.clone()),
).await?;
```

`EventFilter` constructors:

- `::exact(type, id, event_name)` — full match
- `::by_type(type)` — all events of an aggregate type
- `::by_id(type, id)` — all events of one instance
- `::by_event(type, event_name)` — all events of one name

Multiple filters are OR'd; fields within one filter are AND'd. `Args::forward(n, after)` / `Args::backward(n, before)`; `.is_backward()`, `.limit(cap)`. `ReadResult<T>` has `edges: Vec<Edge<T>> { cursor, node }` and `page_info: PageInfo { has_previous_page, has_next_page, start_cursor, end_cursor }`.

The extension trait `AggregateExt` adds `executor.has_event::<Ev>(id)` and `executor.original_version::<Ev>(id)` (the latter reads the latest version — feed it to `append(..).original_version(..)`).

For custom paginated read-models on top of SQL, use `evento::sql::Reader` (it derefs to a sea-query `SelectStatement`) plus `#[derive(evento::Cursor)]` on your row struct — see [`executors.md`](./executors.md).

## Common pitfalls

- **`version = "2"` in Cargo.toml does not resolve alphas.** Cargo only matches pre-releases when the requirement names one — pin `=2.0.0-alpha.26`.
- **`Projection::new::<BankAccount>()` takes the aggregate handle**, not an event struct, and takes **no id** — the id goes to `.load(id)`.
- **Forgetting `original_version`** on appends — it defaults to `0`, which is correct only for the very first event of a new aggregate. Pass the projection's current version (or use `ProjectionAggregate::write()` which fills it in), and handle `WriteError::InvalidOriginalVersion` by reloading.
- **Aggregate type strings are `"{cargo_pkg_name}/{Enum}"`** — renaming the crate breaks reads of old events. Keep the events crate's name stable.
- **Routing key is locked after the first event.** Setting `.routing_key("x")` on an aggregate that already has events is a no-op.
- **`Metadata::default()` generates a new ULID every call** — build once and clone if you want a stable id across a batch.
- **Loads read at most 100 events**; on long histories without snapshots you'll get `Err("Too busy")`. Add bitcode derives to the projection (free snapshots) or use an auto-update subscription.
- **Snapshots are not automatic without bitcode derives** — `#[evento::projection]` alone doesn't add `bitcode::Encode/Decode`; pass them as macro args.
- **Duplicate handlers panic** on both `Projection` and `SubscriptionBuilder` — one handler per (aggregate_type, event_name).
- **`strict()` is off by default** — events with no handler are silently skipped. Turn it on to catch typos.
- **`Default` for the projection state must be sensible** — replay starts from `P::default()` when no snapshot exists.
- **Handler signature is strict.** Projection handlers take `(event: Event<E>, projection: &mut P) -> anyhow::Result<()>`; subscription handlers take `(ctx: &Context<'_, E>, event: Event<EV>) -> anyhow::Result<()>` and must be generic over `E: Executor`. Deviating produces opaque macro errors — see [`macros.md`](./macros.md).
- **A `subscription_all` handler shadows per-event handlers** for the same aggregate type on one subscription (dispatch tries `{type}_all` first). Don't mix them unless that's the intent.
- **Co-keyed secondary aggregates in `.subscription(..)` mode** — a secondary aggregate with a *different* id than the primary is silently not applied. Register the real id with `LoadBuilder::aggregate` (load mode) or resolve the mapping in a manual `SubscriptionBuilder`.
- **Don't `.unwrap()` a load.** `projection.load(id).execute(exec).await` returns `anyhow::Result<Option<T>>`; propagate with `?` and treat `None` as not-found (or tombstoned).
